# DriverGuard

**운전자의 부주의를 줄이기 위한 Android 테스트 앱입니다.**

> [!IMPORTANT]
> **이 저장소는 완성된 제품이 아니라, 앱이 대략 어떤 모습과 흐름으로 동작할지 보여 주기 위한 테스트 앱입니다.**
>
> - **얼굴 인식 기능은 전반적으로 바뀔 예정입니다.** 지금의 분석 방식(MediaPipe 특징점 + 기하 계산 + 시간 규칙)과 임계값은 동작 확인용이며, 실제 얼굴 데이터로 성능을 측정하지 않았습니다. 감지율·오경보율 같은 성능 수치는 없습니다.
> - **디자인도 전반적으로 바뀔 예정입니다.** 화면 구성, 색, 버튼 등은 대략적인 방향을 보여 주는 수준입니다.
> - **백엔드가 연결되어 있지 않습니다.** 서버, 계정, 동기화 없이 기기 안에서만 동작하며, 백엔드가 붙으면 데이터 저장과 흐름도 바뀝니다.
>
> 아래 내용은 현재 테스트 앱의 구현을 기록한 것입니다. 최종 제품의 사양이 아닙니다.

스마트폰 전면 카메라로 운전자의 얼굴을 보고, 졸음 의심 징후와 시각적 부주의(전방 주시 이탈) 의심 징후를 기기 안에서 판정합니다. 징후가 이어지면 단계별로 경고하고 휴식을 권하며, 주행이 끝나면 여정 리포트로 정리합니다. 최종 목표 플랫폼은 차량용 앱 환경인 Pleos Connect입니다. 카메라 입력, 음성 출력, 위치 같은 플랫폼 기능은 교체할 수 있게 분리해 두었습니다.

```text
전면 카메라(CameraX)
  → 얼굴 특징점 478개 추출 (MediaPipe Face Landmarker, 기기 안에서 실행)
  → 눈·입 비율 계산 (기하 계산)  +  머리 자세 계산 (OpenCV solvePnP)
  → 지표별 관측 품질 평가
  → 시간 누적 이벤트 (눈 감김 지속, 눈 감김 비율, 입 벌림, 고개 방향 이탈 …)
  → 판정: 졸음 의심 / 시각적 부주의 의심 (근거 규칙 ID 기록)
  → 경고 (경고음 + 한국어 음성) → 여정 기록(Room) → 여정 리포트
```

## 1. 이 앱이 하는 일과 하지 않는 일

### 하는 일

- **졸음 의심 판정:** 눈 감김이 오래 이어지는지, 일정 시간 동안 눈을 감고 있던 비율이 높은지, 눈 감김이 반복되는지, 입 벌림(하품 의심)이 눈 감김과 함께 반복되는지를 시간 단위로 누적해 판정합니다.
- **시각적 부주의 의심 판정:** 주행 전에 측정한 평소 운전 자세를 기준으로, 고개가 일정 각도 넘게 돌아간 상태가 이어지면 판정합니다.
- **단계별 경고:** 주의 → 휴식 권고 순서로 경고음과 한국어 음성을 냅니다. 같은 경고는 일정 시간 동안 반복하지 않습니다.
- **휴식 안내:** 휴식 권고 상태에서 설치된 지도 앱으로 '휴게소' 검색을 넘깁니다. 앱이 직접 장소를 고르거나 추천하지는 않습니다.
- **여정 기록:** 주행 시간, 유효하게 관측한 시간, 분석이 불가능했던 시간, 이벤트(시작·확인·종료 시각, 근거 규칙, 지표 요약), 휴식, 분석 중단 구간, 선택적으로 위치까지 기기 안에 저장하고 리포트로 보여 줍니다.

### 하지 않는 일

- **별도의 졸음 분류 모델을 학습하지 않습니다.** 이미 학습된 얼굴 특징점 모델(MediaPipe)의 출력에 기하 계산과 Kotlin 시간 규칙을 적용해 판정합니다. 머신러닝 모델을 전혀 쓰지 않는다는 뜻은 아닙니다.
- **확정하지 않습니다.** 결과는 언제나 '징후', '의심', '분석 불가'로 표현합니다.
  - 눈 감김을 감지해도 졸음으로 확정하지 않습니다.
  - 입 벌림이 이어져도 하품으로 확정하지 않습니다.
  - 고개 방향 이탈은 정확한 시선 추적이 아닙니다.
  - 검출된 이벤트가 없어도 안전이 보장되지는 않습니다.
- **점수나 확률을 만들지 않습니다.** 검증되지 않은 '안전 점수'나 '졸음 확률'은 계산하지도 표시하지도 않습니다.
- **영상을 남기지 않습니다.** 원본 영상, 얼굴 이미지, 프레임별 전체 특징점 좌표는 저장하지 않습니다. 네트워크 권한도 없습니다.
- **지어내지 않습니다.** 휴게소 위치, 도착 시간, 주변 차량처럼 측정하지 않은 정보는 만들어 보여 주지 않습니다.
- **백그라운드에서 분석하지 않습니다.** 주행 화면이 보일 때만 분석하고, 화면을 벗어난 구간은 '분석 중단'으로 기록합니다.

> 모든 임계값은 **동작 확인용 개발 시작값**입니다. 실차 데이터나 논문으로 검증한 안전 기준이 아닙니다. 자세한 내용은 [10. 설정값 전체 목록](#10-설정값-전체-목록)을 보세요.

## 2. 빠른 시작

### 2.1 필요한 환경

| 항목 | 요구 사항 |
| --- | --- |
| JDK | 17 |
| Android Studio | AGP 8.12.1을 지원하는 버전 |
| Android SDK | compileSdk 36 |
| 기기 | 전면 카메라가 있는 Android 7.0(API 24) 이상. 유리 효과의 배경 블러는 Android 12(API 31) 이상에서만 보이고, 그 아래 버전은 반투명 면으로 대신합니다 |
| CPU | `arm64-v8a` 또는 `x86_64` (에뮬레이터 포함) |

### 2.2 빌드와 실행

```bash
./gradlew assembleDebug                        # 디버그 APK → app/build/outputs/apk/debug/app-debug.apk
./gradlew installDebug                         # 연결된 기기에 설치
./gradlew test                                 # 판정 엔진 단위 테스트(JVM, 기기 불필요)
./gradlew :analysis:connectedDebugAndroidTest  # OpenCV·MediaPipe 기기 테스트(기기 또는 에뮬레이터 필요)
```

- 모델 파일은 저장소에 들어 있으므로 따로 내려받을 필요가 없습니다([5. 모델 파일](#5-모델-파일)).
- 디버그 APK는 약 130MB입니다. 대부분 OpenCV 네이티브 라이브러리이며, 에뮬레이터용 `x86_64`만 약 55MB입니다. 배포할 때는 ABI별 분할이나 App Bundle을 권장합니다.
- 32비트 기기가 필요하면 `app/build.gradle.kts`의 `abiFilters`에 `armeabi-v7a`를 추가하면 됩니다. MediaPipe와 OpenCV 모두 이 ABI를 제공합니다.

### 2.3 처음 실행할 때의 흐름

1. **홈**에서 카메라 권한을 허용합니다. 카메라 권한이 없으면 주요 버튼이 '카메라 권한 허용'으로 바뀝니다. 위치 권한은 선택입니다.
2. **카메라 위치 확인**을 누릅니다. 정차한 상태에서 평소 운전 자세로 앞을 5초 정도 바라보면 기준값이 측정됩니다.
3. 필요하면 **눈 감김 보정(선택)** 으로 3초 동안 눈을 감아 기준값을 보강합니다.
4. **주행 시작**을 누르면 분석이 시작됩니다.
5. 쉬어야 할 때는 **휴식 시작**, 다시 출발할 때는 **휴식 종료**를 누릅니다.
6. **주행 종료**를 누르면 기록을 저장하고 **여정 리포트**가 열립니다.

## 3. 사용 방법

### 3.1 홈

정차 상태에서 쓰는 화면입니다. 주요 동작은 하나, '카메라 위치 확인'입니다.

- **준비 상태 묶음**
  - **카메라:** 허용 여부. 허용하지 않으면 시작 버튼이 곧 권한 요청 버튼이 됩니다. 영구 거부 상태면 '설정에서 카메라 허용'으로 바뀌어 앱 설정을 엽니다.
  - **위치(선택):** 허용하면 이벤트 위치와 이동 거리를 기록합니다. 없어도 분석과 기록은 동작합니다.
  - **얼굴 특징점 모델:** 모델 파일 확인 결과. 누르면 개발 화면의 모델 정보로 이동합니다. 모델이 없거나 읽지 못하면 오류를 보여 주고 분석을 시작하지 않습니다.
  - **카메라 위치·기준 자세:** 주행마다 정차 상태에서 먼저 확인한다는 안내입니다.
- **오른쪽 위 버튼:** '여정 기록', '개발 화면'.

### 3.2 카메라 위치 확인(캘리브레이션)

- 운전자를 비추는 큰 카메라 창과 얼굴 테두리, 안내 문구, 진행률을 보여 줍니다. 영상 모서리에는 '영상은 저장·전송하지 않음' 표시가 있습니다.
- 유효한 얼굴 샘플을 5초 모으면 완료됩니다. 부족하면 최대 10초까지 연장하고, 그래도 부족하면 실패 이유와 함께 '다시 측정'을 안내합니다.
  - 실패 이유: 얼굴이 충분히 확인되지 않음 / 자세가 흔들림 / 눈을 뜬 상태가 확인되지 않음. 가장 많이 나온 관측 품질 문제(예: '조명이 어둡거나 대비가 낮음')도 함께 표시합니다.
- **눈 감김 보정(선택):** 3초 동안 눈을 감고 있으면 감은 상태의 눈 비율을 측정합니다. 하지 않으면 눈 뜬 기준값에 대한 비율만으로 임계값을 정하는데, 이는 충분히 보정된 값이 아닙니다.
- 측정한 기준값은 **이번 주행에만** 씁니다. 주행이 끝나면 지워지므로 다음 주행에서 다시 측정합니다.

### 3.3 주행

한눈에 읽는 화면이라 스크롤하지 않습니다.

- **상단 캡슐:** 주행 시간, '운전자 화면 보기' 버튼. 좁은 세로 화면에서는 버튼이 얼굴 아이콘으로 줄어듭니다. 한국어 음성을 쓸 수 없는 기기에서는 '경고음만' 안내가 붙습니다.
- **상태 문구:** 큰 제목과 짧은 안내 한 줄입니다.

  | 표시 상태 | 제목 | 안내 |
  | --- | --- | --- |
  | 준비 중 | 관찰 준비 중 | 얼굴과 눈을 확인하고 있습니다 |
  | 관찰 중 | 관찰 중 | 검출된 징후가 없습니다. 안전을 보장하지는 않습니다 |
  | 주의(눈) | 눈 감김 징후 | 눈 감김이 지속되어 감지되었습니다 |
  | 주의(고개) | 시각적 부주의 의심 | 고개 방향 이탈이 지속되고 있습니다. 전방을 주시하세요 |
  | 휴식 권고 | 졸음 의심 | 가까운 안전한 장소에서 휴식을 권합니다 |
  | 분석 불가 | 분석 불가 | 얼굴을 확인할 수 없습니다. 점검은 정차한 뒤에 해 주세요 |
  | 휴식 중 | 휴식 중 | 다시 출발할 때 '휴식 종료'를 누르세요 |

  분석 불가가 쌓이는 중이면 이유(예: '얼굴이 보이지 않음')를 한 줄 더 보여 줍니다.
- **지평선 빛:** 배경 하늘의 지평선 빛 색이 상태를 따라 바뀝니다(관찰 중 청록, 주의 주황, 휴식 권고 빨강, 분석 불가 회청, 휴식 중 보라). 색은 보조 수단이고, 의미는 언제나 문구와 아이콘이 전합니다.
- **조작 레일:** '휴식 시작/휴식 종료'(주요 동작)와 '주행 종료' 두 개만 둡니다. 휴식 권고 상태에서 지도 앱이 있으면 '지도 앱에서 휴게소 찾기'가 나타납니다.
- **경고 상태:** 주의나 휴식 권고일 때는 상단 캡슐이 한 단계 흐려져, 상태 문구와 휴식 버튼에 시선이 모입니다.
- **운전자 화면 보기:** 기본으로는 카메라 영상을 숨깁니다. 켜면 운전자를 비추는 영상 창이 나타나고, 상태 문구는 영상 안 아래쪽에 들어갑니다.
  - 얼굴이 잘 보이도록 영상에는 블러를 쓰지 않습니다. 글자 뒤에만 글자 높이만큼 옅은 그라데이션을 깔아, 얼굴이 있는 위쪽은 가리지 않습니다.
  - 영상 위에는 얼굴 테두리와 개인정보 표시만 함께 그립니다. 창 테두리 색은 상태를 따릅니다.
  - 영상을 숨겨도 분석은 계속됩니다.
- **종료:** 주행 중에 '주행 종료'나 뒤로 가기를 누르면 확인 대화상자가 뜹니다.

### 3.4 휴식

- '휴식 시작'을 누르면 대기 중인 경고를 모두 취소하고, 분석을 멈추고, 휴식 구간을 기록합니다. 진행 중인 이벤트는 `REST_STARTED` 사유로 끝나고, 졸음 의심 판정은 해제됩니다.
- '휴식 종료'를 누르면 새 분석 세션으로 다시 시작합니다. 휴식 전에 제출된 프레임의 늦은 결과는 버립니다.

### 3.5 여정 기록과 리포트

## 5. 모델 파일

| 항목 | 값 |
| --- | --- |
| 파일 | `app/src/main/assets/models/face_landmarker.task` (저장소에 포함) |
| 출처 | `https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/1/face_landmarker.task` (MediaPipe 공식 배포) |
| 라이선스 | Apache License 2.0 |
| 크기 | 3,758,596 bytes |
| SHA-256 | `64184e229b263107bc2b804c6625db1341ff2bb731874b0bcc2fe6544e0bc9ff` |

- 모델은 APK 안에 압축하지 않은 채(`noCompress += "task"`) 들어가고, 앱이 그대로 읽습니다. 설치 후에는 오프라인으로 동작합니다.
- 실행할 때마다 모델의 SHA-256을 계산해 개발 화면에 보여 주고, 위 값과 같은지 표시합니다. 여정에는 `파일명 sha256:앞 12자리`를 남깁니다.
- 모델 파일이 없거나 읽지 못하면 분석을 시작하지 않고, 홈과 주행 화면에 오류를 보여 줍니다.
- 모델 파일을 다시 받으려면 위 출처에서 내려받아 같은 경로에 두고, SHA-256을 확인하세요.

  ```bash
  curl -L -o app/src/main/assets/models/face_landmarker.task \
    https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/1/face_landmarker.task
  shasum -a 256 app/src/main/assets/models/face_landmarker.task
  ```

- 머리 자세 계산(solvePnP)에 쓰는 3D 기준 얼굴은 MediaPipe `canonical_face_model.obj`(Apache 2.0)의 정점을 그대로 옮긴 것입니다.
  - 파일: `domain/.../analysis/geometry/CanonicalFaceModel.kt`
  - 단위는 cm이고, n번째 정점이 n번 특징점에 대응합니다.

## 7. 분석 파이프라인

### 7.1 CameraX 프레임 처리

- **구성:** Preview와 ImageAnalysis를 함께 씁니다. 분석 프레임은 RGBA_8888, 4:3, 640×480을 목표로 합니다.
- **적체 방지**
  - 적체는 `STRATEGY_KEEP_ONLY_LATEST`로 막습니다.
  - 분석 제출 빈도는 `targetAnalysisFps`(기본 12)로 제한합니다.
  - 이전 추론이 끝나지 않았으면 새 프레임을 버립니다. 한 번에 한 프레임만 처리합니다.
  - 카메라 FPS, 분석 제출 빈도, 화면 지표 갱신 간격(`uiRefreshMs`)은 서로 별개입니다.
- **스레드:** 변환은 전용 단일 스레드에서, 추론은 MediaPipe 내부 스레드에서 합니다. 메인 스레드에서는 처리하지 않습니다. 모델과 OpenCV 인스턴스는 세션 동안 한 번만 만듭니다.
- **버퍼 소유권(독립 버퍼 복사)**
  - `ImageProxy`의 RGBA 버퍼를 앱이 소유한 재사용 Bitmap에 복사하고, `finally`에서 바로 닫습니다. 성공, 예외, 건너뛰기 모든 경우에 닫습니다.
  - 복사본은 결과 콜백이 오기 전까지 다시 채우지 않습니다.
  - 복사할 때 `rowStride`와 `pixelStride`를 고려해 행 단위로 처리합니다.
  - 회전 보정용 Bitmap, Canvas, Matrix도 재사용합니다.
- **타임스탬프**
  - 프레임을 받은 시점의 `elapsedRealtime`(ms)를 `detectAsync`에 넘깁니다. 이전 값 이하이면 1ms를 올려 단조 증가를 지킵니다.
  - 결과의 `timestampMs()`로 원래 프레임 시각을 되찾습니다. 콜백이 도착한 시각은 쓰지 않습니다.
  - 센서 타임스탬프는 기기마다 시간 기준이 달라 쓰지 않았습니다.
- **세션 토큰**
  - 프레임을 제출할 때의 분석 세션 토큰이 결과에 따라옵니다.
  - 휴식, 앱 백그라운드 전환, 여정 종료가 일어나면 토큰을 바꿔, 이전 세션의 늦은 콜백을 버립니다(`AnalysisSessionGate`).
  - 엔진도 재개 시각 이전에 촬영된 관측은 버립니다.
- **생명주기**
  - 백그라운드에서는 분석하지 않습니다. 주행 화면이 `ON_STOP`이 되면 `APP_BACKGROUND` 중단 구간을 기록하고, `ON_START`에서 재개합니다.
  - 카메라 오류는 `CAMERA_ERROR` 중단으로 기록합니다.
  - 화면을 닫으면 카메라와 추론 리소스를 정리합니다. 사용자가 '주행 종료'를 누르지 않고 화면이 사라져도 여정을 닫습니다.
  - 앱이 강제 종료되어 열린 채 남은 여정은 다음 실행 때 '비정상 종료'로 정리합니다.

### 7.2 좌표계

| 좌표계 | 정의 |
| --- | --- |
| 원본 카메라 버퍼 | 센서 방향 RGBA, `rotationDegrees` 미적용 |
| 분석 이미지 | `rotationDegrees`만큼 회전한 정방향 이미지. **미러링하지 않습니다** |
| 특징점 정규화 좌표 | 분석 이미지 기준 0~1. 거리를 계산할 때는 x에 너비, y에 높이를 곱한 픽셀 좌표로 바꿉니다(`LandmarkPoints.fromNormalized`). 정규화 z는 쓰지 않습니다 |
| 화면 Preview | PreviewView `FILL_CENTER`(가운데 채움). 전면 카메라라 거울상이며, 오버레이를 그릴 때만 x를 뒤집습니다(`PreviewMapping`) |

### 7.3 특징점 정의(`FaceLandmarkIndices`)

좌우는 운전자 본인 기준입니다. 미러링하지 않은 이미지에서는 운전자의 오른쪽 눈이 이미지 왼쪽에 있습니다.

| 지표 | 인덱스 |
| --- | --- |
| 오른쪽 눈 EAR p1..p6 | 33, 160, 158, 133, 153, 144 |
| 왼쪽 눈 EAR p1..p6 | 362, 385, 387, 263, 373, 380 |
| 입술 안쪽 세로 쌍 | (13,14), (82,87), (312,317) |
| 입 가로(입꼬리) | 61, 291 |
| solvePnP 점(표정 영향이 적은 점) | 10 이마, 168 미간, 6 콧등, 1 코끝, 98·327 콧볼, 33·133·362·263 눈꼬리 |

인덱스는 세 가지 방법으로 검증했습니다.

1. **단위 테스트:** 공식 기준 얼굴 좌표에서 p2↔p6, p3↔p5가 같은 x의 위·아래 눈꺼풀이고, p1·p4가 눈의 양 끝인지 확인합니다.
2. **기기 테스트:** 모든 인덱스가 `FaceLandmarker.FACE_LANDMARKS_LEFT_EYE / RIGHT_EYE / LIPS` 공식 연결 정의에 속하는지 확인합니다.
3. **개발 화면:** 인덱스 번호와 EAR 윤곽, 입 세로선을 영상 위에 그려 눈으로 확인할 수 있습니다.

### 7.4 계산식

- **EAR(눈 종횡비)** = (|p2−p6| + |p3−p5|) / (2·|p1−p4|)
  - 왼쪽·오른쪽 눈을 각각 계산합니다.
  - 눈 너비가 `minEyeWidthPx`보다 작거나 좌표가 유한하지 않으면 무효입니다.
- **입 벌림 비율** = 입술 안쪽 세 세로 쌍의 거리 평균 / 입꼬리 사이 너비
- **머리 자세**
  1. solvePnP(ITERATIVE)로 카메라 기준 얼굴 회전 R_cm을 구합니다.
  2. 운전자가 카메라를 정면으로 볼 때 R_cm = F = diag(1, −1, −1)이므로, 머리 회전을 H = F·R_cm으로 둡니다.
  3. H = Ry(yaw)·Rx(pitch)·Rz(roll)로 분해합니다(Y → X → Z 내재 회전).
     - yaw + : 운전자 기준 왼쪽으로 돌림
     - pitch + : 고개 숙임
     - roll + : 오른쪽 어깨 쪽 기울임
  4. 판정에는 기준 대비 상대 회전 **H_rel = H_baseᵀ·H**를 먼저 구한 뒤 각도로 해석합니다. 각도끼리 빼면 생기는 경계각 문제를 피하기 위해서입니다.
- **카메라 내부 파라미터는 근사치입니다.** 초점거리는 분석 이미지의 긴 변, 주점은 이미지 중심, 왜곡은 0으로 둡니다. 회전 보정한 분석 이미지 크기로 매 프레임 다시 만듭니다.
  - 절대 각도의 정확도는 보장하지 않으며, 판정은 상대 회전으로만 합니다.
  - 실제 렌즈 보정값을 쓰려면 `CameraIntrinsics`에 넘기면 됩니다. 아직 구현하지 않았습니다.
- **자세 무효 조건:** solvePnP 실패, tvec.z ≤ 0, 얼굴이 카메라를 등진 해, |각도| > 90°, 평균 재투영 오차 / 얼굴 너비 > `maxReprojectionErrorRatio`.
- MediaPipe 얼굴 변환 행렬(facialTransformationMatrixes)은 쓰지 않고 출력도 끕니다. 두 방식의 좌표계가 같다고 가정하지 않으며, 대체 구현은 확장 지점으로 남겼습니다.

### 7.5 관측 품질(`QualityFlag`)

| 값 | 화면 문구 | 조건 |
| --- | --- | --- |
| `VALID` | 유효 | |
| `FACE_NOT_FOUND` | 얼굴이 보이지 않음 | 얼굴 미검출 |
| `MULTIPLE_FACES` | 여러 얼굴이 보여 운전자를 특정할 수 없음 | 얼굴 2개 이상 |
| `FACE_TOO_SMALL` | 얼굴이 너무 작거나 잘림 | 얼굴 너비 비율 < `minFaceWidthRatio`, 또는 이미지 밖으로 `maxFaceOutsideRatio` 이상 나감 |
| `LANDMARKS_INVALID` | 특징점이 불안정함 | 특징점 누락·비정상 좌표, 눈(한쪽이라도)이나 입 지표 계산 불가, 자세 계산 실패, 재투영 오차 / 얼굴 너비 > `maxReprojectionErrorRatio` |
| `EXCESSIVE_HEAD_ROTATION` | 고개 회전이 커서 눈·입 지표를 계산할 수 없음 | 기준 대비 yaw > `metricMaxYawDeg` 또는 pitch > `metricMaxPitchDeg` |
| `LOW_LIGHT_OR_LOW_CONTRAST` | 조명이 어둡거나 대비가 낮음 | 얼굴 영역 밝기 평균 < `minFaceLuma` 또는 표준편차 < `minFaceLumaStdDev` |
| `FRAME_GAP` | 카메라 영상이 끊김 | 관측 간격 > `maxContinuityGapMs`, 또는 관측이 들어오지 않음 |
| `CALIBRATION_REQUIRED` | 캘리브레이션 필요 | 기준값이 없어 상대 지표를 계산할 수 없음 |
| `ANALYSIS_ERROR` | 분석 오류 | 추론·계산 예외 |

- **지표별로 따로 평가합니다.** 얼굴 전체, 눈, 입, 자세의 품질을 각각 매깁니다. 예를 들어 기준 대비 yaw가 30°를 넘으면 눈·입 지표는 무효가 되지만, 자세로는 고개 방향 이탈을 계속 판정합니다.
- **양쪽 눈이 모두 유효할 때만 눈 지표를 씁니다.** 한쪽만 유효하면 보수적으로 무효로 보므로, 윙크나 한쪽 추적 실패가 '양쪽 눈 감김'이 되지 않습니다.
- **얼굴이 둘 이상이면 분석을 보류합니다.** 첫 번째 얼굴을 운전자로 고르지 않습니다. 차량용 운전자 영역 선택은 확장 지점입니다.
- **신뢰도를 지어내지 않습니다.** MediaPipe는 특징점별 신뢰도를 주지 않으며, 앱도 그런 값을 만들지 않습니다. 검출·추적 임계값(0.5)은 MediaPipe 내부 설정일 뿐입니다.
- **밝기로 가림을 판별하지 않습니다.** 조도 검사는 얼굴 경계 안 16×16 격자의 밝기 평균과 표준편차로 극단적인 저조도·저대비만 거릅니다. 선글라스나 손 가림은 신뢰성 있게 구분할 수 없으므로, 특징점이 계속 추정되는 한 가려진 눈의 EAR은 틀릴 수 있습니다.

### 7.6 캘리브레이션(주행마다, 정차 상태)

- **안내 문구:** "카메라 위치를 맞추고 평소 운전 자세로 앞을 바라봐 주세요."
- **수집:** 유효 샘플을 5초(`calibrationTargetMs`) 모읍니다. 유효 시간 비율(`calibrationMinCoverage`, 60%)이나 샘플 수(`calibrationMinSamples`, 25개)가 부족하면 최대 10초(`calibrationMaxMs`)까지 연장하고, 그래도 부족하면 완료하지 않고 실패 이유를 보여 줍니다.
- **기준값**
  - 양쪽 눈 EAR과 다문 입 비율은 **중앙값**을 씁니다. 순간 깜빡임과 이상값에 강건합니다.
  - yaw·pitch·roll도 중앙값을 쓰고, 기준 회전 행렬은 중앙값 자세에 가장 가까운 실제 샘플의 행렬로 정합니다.
  - 얼굴 크기를 함께 기록합니다.
- **변동성 검사:** EAR과 yaw·pitch의 사분위 범위를 구합니다. 자세 사분위 범위가 6°(`calibrationMaxPoseIqrDeg`)를 넘으면 '자세가 흔들렸습니다'로 실패합니다.
- **눈 감김 보정(선택, 3초):** 감은 상태의 EAR 중앙값을 측정해 임계값을 '감은 값과 뜬 값 사이의 위치'로 정합니다. 하지 않으면 눈 뜬 기준값에 대한 비율만 쓰며, **이는 충분히 보정된 값이 아닙니다.** 개발 화면에서는 이 경우 임계값에 `*`를 붙입니다.
- **보관 범위:** 기준값은 메모리에만 두고 그 주행에만 씁니다. 주행이 끝나면 지워, 카메라 위치가 바뀌었을 수 있는 기준값을 다시 쓰지 않습니다. 사용자별 프로필 저장은 구현하지 않았습니다.

## 8. 시간 기반 판정

### 8.1 공통 시간 규칙

- 지속 시간은 프레임 수가 아니라 **관측 타임스탬프(단조 시계)** 로 계산합니다. 저장과 표시에는 벽시계를 씁니다.
- **관측 → 구간 변환:** 관측 i는 [t_i, t_{i+1}) 구간을 대표합니다. 간격이 `maxContinuityGapMs`(300ms)를 넘으면 그 사이는 '관측 없음'으로 처리하고, 직전 상태로 채우지 않습니다.
- 공백이 생기면 진행 중인 지속 구간(눈 감김 등)을 마지막 관측 시각에서 끊고, 종료 사유에 `OBSERVATION_GAP`을 남깁니다.
- 분석 불가 구간은 정상으로도, 눈 감김으로도 바꾸지 않습니다.
- 프레임 속도가 10·15·30fps로 달라도 같은 상황이면 같은 결과가 나오도록 테스트합니다.

### 8.2 지표 이벤트

| 이벤트 | 조건 |
| --- | --- |
| **지속적 눈 감김** | EAR에 3프레임 중앙값 필터와 히스테리시스를 적용합니다. **양쪽 모두** 닫힘 임계값 아래면 닫힘, **어느 한쪽이라도** 열림 임계값 위면 열림, 그 사이는 이전 상태를 유지합니다. 연속된 유효 관측에서 닫힘이 1.5초 이상 이어지면 이벤트입니다 |
| **눈 감김 비율**(PERCLOS 유사 지표) | 60초 창에서 (유효 관찰 중 감김 시간 / 유효 관찰 시간). 창 경계에서 구간을 잘라 계산하고, 무효 구간은 분자·분모 모두에서 뺍니다. 창이 다 차기 전에는 '측정 중', 유효 관측률이 80% 미만이면 '판정 보류'입니다. **표준 PERCLOS와 같다고 보지 않습니다** |
| **지속적 입 벌림**(하품 의심) | 다문 입 기준 + 0.30 초과면 벌림, + 0.18 미만이면 닫힘. 2초 이상 이어지면 이벤트입니다. 끝난 뒤 5초 안에 다시 벌어지면 새 이벤트로 세지 않습니다. **말하기·노래·웃음과 구분하지 못합니다** |
| **고개 방향 이탈** | 기준 대비 \|yaw\| > 25° 또는 \|pitch\| > 20°로 진입하고, 진입 각도의 0.8배 안으로 들어오면 복귀입니다. 2초 이상 이어지면 이벤트입니다. 사이드미러 확인이나 교차로 좌우 확인과 완벽히 구별하지는 못합니다 |
| **반복적 고개 숙임**(실험) | pitch가 +12° 넘게 숙였다가 절반 아래로 돌아오기까지 0.15~1.5초가 걸리면 1회로 셉니다. 60초 안에 3회면 기록합니다. **기본 설정에서는 졸음 판정에 쓰지 않습니다** |
| **분석 불가** | 눈 지표를 쓸 수 없는 상태(미검출, 복수 얼굴, 무효, 공백 등)가 3초 이상 이어지면 이벤트입니다 |

**이벤트의 생명주기:** 후보 시작 → 지속 조건 충족(확인, 레코드 생성) → 종료 조건 → 저장.

- 저장 항목: 후보 시작 시각, 확인 시각, 종료 시각, 유효 지속 시간, 종료 사유, 근거 규칙, 지표 요약(최소 EAR, 최대 각도 등).
- 같은 이벤트를 프레임마다 새로 만들지 않습니다.
- **종료 사유**

  | 값 | 의미 |
  | --- | --- |
  | `RECOVERED` | 지표가 정상 범위로 돌아옴 |
  | `OBSERVATION_GAP` | 관측 공백으로 끊김 |
  | `OBSERVATION_INVALID` | 지표 계산 불가로 끊김 |
  | `HOLD_EXPIRED` | 판정 근거가 다시 생기지 않아 유지 시간 만료 |
  | `REST_STARTED` | 휴식 시작 |
  | `APP_PAUSED` | 앱이 화면을 벗어남 |
  | `TRIP_ENDED` | 주행 종료 |
  | `ABNORMAL_TERMINATION` | 비정상 종료 후 다음 실행 때 정리 |

### 8.3 판정

두 판정은 서로 독립적으로 유지합니다. 졸음 의심이 있어도 시각적 부주의 의심은 따로 판정하고, 반대도 마찬가지입니다.

| 판정 | 규칙 ID | 조건 |
| --- | --- | --- |
| **졸음 의심 → 휴식 권고** | `CLOSED_RATIO` | 눈 감김 비율 ≥ 0.15 (유효 관측률을 충족할 때만) |
| | `REPEATED_CLOSURE` | 5분 안에 지속적 눈 감김 3회 |
| | `YAWN_WITH_CLOSURE` | 5분 안에 입 벌림 2회 + 지속적 눈 감김 1회 이상 |
| 보조(단계만 상향) | `SUPPORT_YAWN`, `SUPPORT_NOD` | 졸음 의심 중 입 벌림 반복이 함께 관찰됨(고개 숙임은 설정으로 켰을 때만) |
| **시각적 부주의 의심 → 주의** | `HEAD_AWAY` | 기준 자세 대비 고개 방향 이탈이 2초 이상 지속 |
| 주의(지표) | `EYE_SUSTAINED` | 지속적 눈 감김 |

- 판정 레코드에는 적용한 규칙 ID와 지표 요약(비율, 관측률, 횟수)이 함께 남습니다.
- 졸음 의심은 마지막 근거로부터 60초(`drowsinessHoldMs`) 동안 유지되고, 휴식을 시작하면 해제됩니다. 반복 규칙에 이미 쓴 근거는 다시 쓰지 않습니다.
- 주의 표시와 시각적 부주의 의심은 원인이 끝난 뒤 3초(`cautionHoldMs`) 동안 유지해, 표시가 깜빡이지 않게 합니다.
- **시각적 부주의 판정의 범위는 머리 방향으로 본 전방 주시 이탈뿐입니다.** 눈만 돌린 경우는 놓칠 수 있고, 인지적 부주의(딴생각)는 판정하지 않습니다.
- **낮은 신뢰도의 관측이 높은 경고로 바로 이어지지 않습니다.**
  - 비율 판정에는 관측률 조건이 있습니다.
  - 눈 감김은 양쪽 눈이 유효한 연속 관측에서만 셉니다.
  - 분석 불가는 '분석 불가' 안내로만 이어집니다.

### 8.4 표시 상태

엔진은 지표별 관측 가능 여부와 활성 판정을 잃지 않은 채, 화면용으로만 하나의 표시 상태로 집계합니다.

| 표시 상태 | 조건 |
| --- | --- |
| `PREPARING` 준비 중 | 시작 직후, 휴식 종료 직후, 첫 유효 관측 대기 |
| `OBSERVING` 관찰 중 | 유효 관측 중이고 활성 판정 없음 |
| `CAUTION` 주의 | 지속적 눈 감김 또는 고개 방향 이탈(원인 구분: `CautionCause`) |
| `REST_RECOMMENDED` 휴식 권고 | 졸음 의심 |
| `UNAVAILABLE` 분석 불가 | 눈 지표 계산 불가가 안내 지연 시간 이상 지속 |
| `PAUSED` 휴식 중 | 사용자가 휴식 시작 |

## 9. 경고

- **우선순위:** 휴식 권고 > 눈 감김 주의 > 고개 이탈 주의 > 분석 불가.
- **반복 제한**은 종류별로 따로 둡니다. 주의 20초, 휴식 권고 60초, 분석 불가 60초입니다.
  - 낮은 단계의 반복 제한이 휴식 권고를 막지 않습니다.
  - 반복 제한 때문에 소리를 내지 않아도 이벤트는 기록합니다.
  - 상태가 짧게 오락가락해도 같은 경고가 연달아 나지 않습니다.
- **재생 방식**
  - 주의(눈·고개)와 휴식 권고는 경고음이 끝난 뒤 음성이 나오므로 둘이 겹치지 않습니다. 분석 불가는 경고음 없이 음성만 냅니다.
  - 재생 중에는 더 높은 우선순위의 경고만 끊고 들어갑니다.
  - 재생하는 동안만 오디오 포커스를 잡고(일시, 다른 소리 줄이기) 끝나면 돌려줍니다.
  - TTS 초기화에 실패하거나 한국어 음성이 없으면 경고음만 내고, 화면에 그렇게 표시합니다.
- **취소:** 휴식 시작, 주행 종료, 백그라운드 전환 때 대기 중인 경고를 모두 취소합니다.
- **음성 문구**
  - 주의(눈): "눈 감김이 지속되어 감지되었습니다."
  - 주의(고개): "고개 방향 이탈이 지속되고 있습니다."
  - 휴식 권고: "가까운 안전한 장소에서 휴식을 권합니다."
  - 분석 불가: "얼굴을 확인할 수 없어 분석이 일시 중단되었습니다. 점검은 정차한 뒤에 해 주세요."
- 주행 중에 카메라를 조정하라고 유도하지 않습니다. 점검은 언제나 '정차한 뒤에'로 안내합니다.

| --- | --- |

`tripId`, `startedAtMs`, `endedAtMs`, `durationMs`

### `interruptions` — 분석 중단

`tripId`, `reason`(`REST`, `APP_BACKGROUND`, `CAMERA_ERROR`), `startedAtMs`, `endedAtMs`, `durationMs`

### 위치 기록 규칙

- 이벤트 확인 시각과 10초 넘게 차이 나거나 정확도가 50m보다 나쁜 위치는 붙이지 않습니다. 오래된 마지막 위치를 그대로 쓰지 않습니다.
- 위치 권한이 없어도 분석, 경고, 기록은 동작합니다.
- 지도나 내비게이션 연동은 없습니다. 리포트에는 좌표와 이벤트 목록으로만 보여 줍니다.

### 기타 저장

- **설정:** SharedPreferences `analysis_config`에 `AnalysisConfig`를 JSON으로 저장합니다.
- **수치 로그**(개발 화면에서 명시적으로 시작할 때만): 앱 내부 저장소 `files/metric_logs/*.csv`에 프레임별 수치 지표만 기록합니다. 이미지와 특징점 좌표는 넣지 않습니다. 개발 화면에서 지울 수 있습니다.
- **백업:** `android:allowBackup="false"`로 기기 백업에 포함하지 않습니다.

## 12. 화면과 디자인

| 화면 | 라우트 | 내용 |
| --- | --- | --- |
| 홈 | `HomeRoute` | 소개 문구, 준비 상태(카메라·위치·모델·기준 자세), '카메라 위치 확인', 여정 기록·개발 화면 진입 |
| 카메라 위치 확인 | `CalibrationRoute` | 카메라 창과 얼굴 테두리, 안내, 진행률, 실패 사유, 눈 감김 보정(선택), 주행 시작 |
| 주행 | `DrivingRoute` | 상태 문구, 주행 시간, 운전자 화면 보기, 휴식·종료 |
| 여정 기록 | `TripListRoute` | 여정 목록 |
| 여정 리포트 | `TripDetailRoute(tripId)` | 요약, 판정·이벤트 집계, 휴식·중단, 위치, 타임라인 |
| 개발 화면 | `DevSettingsRoute` | 실시간 / 임계값 / 모델·성능 |

- **가로 우선:** 대시보드 거치와 차량 중앙 디스플레이를 기준으로 가로 화면을 먼저 설계했고, 세로 화면도 지원합니다. 화면 폭 600dp를 기준으로 두 영역 배치와 한 줄 배치를 바꿉니다.
- **디자인 방향 '블루아워 드라이브':** 해 뜨기 직전 하늘을 추상화한 배경 위에 반투명 유리 질감의 조작 요소(Liquid Glass 방식)를 띄웁니다. 지평선 빛의 색이 운전자 상태를 따라 바뀝니다. 다크 테마로 고정해 야간·터널 주행에서 눈부심을 줄입니다.
- **일관성:** 모든 버튼, 분할 컨트롤, 아이콘 버튼의 높이는 56dp 하나로 맞췄고, 화면마다 스크롤은 하나만 둡니다.
- **접근성:** 상태를 색만으로 전하지 않고, 아이콘 버튼에는 스크린 리더 이름을 붙입니다. 상태 변화는 스크린 리더가 읽도록 라이브 영역으로 묶었습니다. 시스템 글자 크기 확대, 애니메이션 끄기, 고대비 텍스트(유리 대신 불투명 면) 설정을 따릅니다.
- **서체:** Pretendard(SIL OFL)를 쓰고, 한국어는 어절 단위로 줄을 바꿉니다(Android 13 이상).
- 색, 서체, 간격, 구성 요소의 자세한 규칙은 [`DESIGN.md`](DESIGN.md)에 있습니다. 색 원시값은 `views/theme/Palette.kt`, 의미 토큰은 `views/theme/Theme.kt`에만 있습니다.
- `docs/screenshots/`의 이미지는 이전 버전의 화면이며, 현재 디자인과 다릅니다.

## 14. 테스트와 검증 결과

### 14.1 자동 테스트

**JVM 단위 테스트 48개**가 모두 통과합니다(`./gradlew test`).

| 테스트 파일 | 개수 | 다루는 내용 |
| --- | --- | --- |
| `GeometryTest` | 6 | 공식 기준 얼굴로 EAR 인덱스 대응 확인, 얼굴 크기(거리)가 바뀌어도 EAR·입 비율 일정, 분모 0·NaN·Infinity는 무효, 종횡비가 달라도 같은 EAR(좌표 변환), 오일러각 왕복과 상대 회전의 일관성, 미러링하지 않은 이미지에서의 머리 방향 부호 |
| `CalibrationTest` | 6 | 깜빡임·이상값에 강건한 기준값, 샘플 부족 시 연장 후 실패 이유 제공, 처음에 얼굴이 없어도 최대 시간 안에 완료, 자세 흔들림 실패, 눈 감김 보정 기록과 실패, 여러 얼굴이면 무효 |

| `ClosedEyeRatioTest` | 7 | 창 경계에서 구간 자르기, 창이 차기 전 '측정 중', 유효 관측 없음, 분석 불가 구간 제외와 관측률 부족 시 보류, 기준 이상이면 졸음 의심, 관측률이 낮으면 판정하지 않음, 측정 중에는 판정하지 않음 |
| `JudgmentTest` | 12 | 짧은 고개 돌림과 지속 이탈 구분, 진입·복귀 기준 분리, 고개를 크게 돌리면 눈 지표만 무효, 반복 눈 감김 → 졸음 의심·휴식 권고, 입 벌림 한 번은 휴식 권고 아님, 입 벌림 반복 + 눈 감김 → 졸음 의심과 보조 징후, 입 벌림 재발 간격, 졸음 의심 유지 만료, 끄덕임은 실험 이벤트로만, 휴식 시작 시 이벤트 종료와 재개 전 관측 폐기, 주행 종료 시 이벤트 종료, 캘리브레이션 없으면 상대 지표 판정 안 함 |
| `TripRecorderTest` | 8 | 상태가 진동해도 경고 반복 제한 준수와 이벤트 기록, 높은 단계 경고는 낮은 단계 제한에 막히지 않음, 주행 종료 시 이벤트를 사유와 함께 종료, 이전 세션의 늦은 콜백 무시, 오래되거나 부정확한 위치 제외, 실제·시연 기록 구분 저장, 앱이 화면을 벗어나면 중단 구간 기록과 관측 폐기, 반복 제한 중에도 이벤트 기록 |

**기기 테스트 2개**가 통과합니다(`:analysis:connectedDebugAndroidTest`, 에뮬레이터 Pixel 3, API 30, arm64).

- 합성 3D 점을 투영한 뒤 OpenCV solvePnP로 자세를 복원합니다. 5개 자세에서 yaw·pitch·roll이 ±1° 안이었고 부호도 일치했습니다. 재투영 오차는 0.5px 미만이었습니다.
- 특징점 인덱스가 MediaPipe 공식 연결 정의에 속하는지 확인했습니다.

### 14.2 직접 확인한 것

에뮬레이터(얼굴이 없는 가상 카메라 장면)에서 확인했습니다.

- CameraX → MediaPipe → 품질 평가가 동작해, 캘리브레이션이 '얼굴이 보이지 않음'으로 10초 뒤 실패를 안내합니다.
- 앱을 다시 설치해 끊긴 여정은 다음 실행 때 '비정상 종료'로 정리됩니다.
- 측정값(얼굴 없음, 276프레임)
  - 처리량 10.0fps(목표 12fps가 카메라 프레임 간격에 맞춰 양자화됨)
  - 추론 지연 최근 9.5ms / 평균 15.6ms
  - 추론 중이라 버린 프레임 0, 오류 0

실제 기기(Galaxy S20, Android 13)에서는 설치, 홈, 권한, 모델 확인 화면을 확인했습니다.

### 14.3 아직 측정하지 못한 것

실제 얼굴과 긴 시간 주행이 필요한 항목입니다.

- 실제 얼굴에서의 특징점 위치, EAR·입 비율 값의 범위, 자세 부호(좌우·위아래)
- 얼굴이 있을 때의 추론 지연(특징점 모델이 추가로 실행됨)
- 장시간 메모리, 발열, 처리 속도
- 안경, 조명 변화, 얼굴 일부 가림
- 말하기, 웃음에 따른 오경고
- 백그라운드 전환과 복귀, 권한 거절·철회의 실제 흐름
- 실제 TTS 음성(에뮬레이터에는 한국어 음성이 없어 경고음만 확인)

### 14.4 실제 기기 검증 계획

| 항목 | 확인할 것 |
| --- | --- |
| 자세 | 정면, 좌우 회전, 고개 숙임에서 각도 부호와 이탈 판정 |
| 평소 행동 | 평소 깜빡임, 말하기, 웃음에서 오경고가 나지 않는지 |
| 환경 | 안경, 조명 변화, 가림 |
| 지속성 | 30분 이상 연속 실행(메모리, 발열, 처리량) |
| 생명주기 | 앱 전환, 화면 꺼짐, 권한 철회 |

정차 상태의 연출 테스트는 **이벤트 동작 검증**일 뿐, 실제 졸음 검출 성능 검증이 아닙니다. **졸음이나 위험 행동을 실제 도로에서 유도하는 테스트는 하지 마세요.**

## 17. Pleos Connect 연동 전 확인할 것

- **카메라**
  - 차량 실내 카메라(DMS)의 접근 API, 해상도, 프레임 레이트, 적외선 여부를 확인해야 합니다. 적외선 흑백 영상에서는 MediaPipe 성능을 다시 검증해야 합니다.
  - 렌즈 내부 파라미터를 받을 수 있는지 확인해야 합니다.
  - `CameraFrameSource`를 차량 카메라 입력으로 바꾸고, 회전·미러 규약을 다시 맞춰야 합니다.
- **운전자 영역:** 조수석 탑승자 등으로 얼굴이 여러 개 보일 때 운전자를 고르는 방법이 필요합니다. 지금은 분석을 보류합니다.
- **SDK와 배포**
  - Pleos SDK 제공 여부와 라이선스를 확인해야 합니다.
  - 차량용 앱 배포 조건(ABI, APK 크기, 16KB 페이지 정렬, 백그라운드·포그라운드 서비스 정책)을 확인해야 합니다.
  - 주행 중 화면 사용 제한(Driver Distraction 가이드라인)을 확인해야 합니다.
- **음성, 위치, 지도**
  - 차량 음성 출력 채널과 오디오 포커스 정책을 확인해야 합니다.
  - 차량 위치와 내비게이션 API를 확인해야 합니다.
  - 교체 지점은 `domain/.../platform/PlatformInterfaces.kt`(`ILocationSource`, `IAlertOutput`, `IRestAreaGuide`)와 `app/.../PlatformLocator.kt`입니다.
- **법규와 인증:** 운전자 모니터링 기능 관련 규정(예: 졸음·주의 경고 시스템 요구사항)을 검토해야 하며, 인증 여부에 따라 표현과 기능 범위를 조정해야 합니다.

## 18. 문제 해결

| 증상 | 원인과 해결 |
| --- | --- |
| Android Studio에서 "incompatible version (AGP …)" 동기화 오류 | 사용하는 Android Studio가 지원하는 AGP 버전보다 높게 설정된 경우입니다. 이 프로젝트는 AGP 8.12.1을 씁니다. Android Studio를 최신으로 올리거나, `gradle/libs.versions.toml`의 `agp` 값을 Studio가 안내하는 버전으로 맞추세요 |
| 홈에 '모델 파일이 없습니다' | `app/src/main/assets/models/face_landmarker.task`가 없거나 깨졌습니다. [5. 모델 파일](#5-모델-파일)의 명령으로 다시 받고 SHA-256을 확인하세요 |
| 캘리브레이션이 '얼굴이 충분히 확인되지 않았습니다'로 실패 | 얼굴이 화면에 충분히 크게, 잘리지 않게 들어오는지 확인하세요. 함께 표시되는 품질 사유(어두움, 여러 얼굴, 얼굴 작음)를 먼저 해결하세요 |
| 캘리브레이션이 '자세가 흔들렸습니다'로 실패 | 측정하는 5초 동안 평소 운전 자세로 앞을 보고 고개를 움직이지 마세요 |
| 캘리브레이션이 '눈을 뜬 상태가 확인되지 않았습니다'로 실패 | 측정 중에 눈을 자연스럽게 뜨고 계세요. 조명이 너무 어두우면 특징점이 불안정할 수 있습니다 |
| 주행 화면에 '경고음만' | 기기에 한국어 TTS 음성이 없거나 초기화에 실패했습니다. 시스템 설정의 텍스트 음성 변환에서 한국어 음성 데이터를 설치하세요 |
| 주행 중 '분석 불가'가 자주 뜸 | 개발 화면 '실시간' 탭에서 지표별 무효 사유를 확인하세요. 카메라 위치, 조명, 고개 각도가 흔한 원인입니다. 점검은 정차한 뒤에 하세요 |
| '지도 앱에서 휴게소 찾기' 버튼이 보이지 않음 | `geo:` 인텐트를 처리하는 지도 앱이 설치되어 있지 않습니다 |
| 유리 효과에 블러가 없음 | Android 12 미만에서는 블러 대신 반투명 면을 씁니다. 고대비 텍스트 설정을 켜면 불투명 면을 씁니다 |
| APK가 큼(약 130MB) | OpenCV 네이티브 라이브러리 때문입니다. 배포 시 ABI 분할이나 App Bundle을 쓰세요 |
